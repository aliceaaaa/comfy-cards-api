# Comfy cards API

Бэкенд для [comfy-cards](https://github.com/aliceaaaa/comfy-cards): аккаунты и колоды карточек.
Fastify + TypeScript + PostgreSQL, без ORM — обычный SQL через `pg`.

## Запуск локально

Нужен PostgreSQL. Проще всего в докере:

```bash
docker run -d --name comfy-cards-db -e POSTGRES_PASSWORD=postgres -p 5433:5432 postgres:16
```

Дальше:

```bash
cp .env.example .env
npm install
npm run dev
```

Миграции применяются сами при старте, отдельно — `npm run migrate`.

## Переменные окружения

| Переменная     | Обязательна | Что это                                                        |
| -------------- | ----------- | -------------------------------------------------------------- |
| `DATABASE_URL` | да          | Строка подключения к Postgres                                   |
| `JWT_SECRET`   | да          | Секрет для подписи токенов, минимум 32 символа                  |
| `WEB_ORIGIN`   | нет         | Разрешённые источники через запятую. Пусто — разрешены любые     |
| `PORT`         | нет         | Порт, по умолчанию 3001                                          |

Если переменные заданы неверно, сервер не стартует и пишет, что именно не так.

## API

Все ответы — JSON. Ошибка всегда одной формы: `{ "error": "текст" }`.
Защищённые роуты требуют заголовок `Authorization: Bearer <token>`.

| Метод    | Путь             | Доступ | Что делает                                 |
| -------- | ---------------- | ------ | ------------------------------------------ |
| `GET`    | `/health`        | всем   | Проверка живости, используется Railway      |
| `POST`   | `/auth/register` | всем   | Регистрация, возвращает токен и юзера       |
| `POST`   | `/auth/login`    | всем   | Вход, возвращает токен и юзера              |
| `GET`    | `/auth/me`       | токен  | Текущий пользователь                        |
| `GET`    | `/decks`         | токен  | Колоды пользователя, новые сверху           |
| `POST`   | `/decks`         | токен  | Создать колоду                              |
| `GET`    | `/decks/:id`     | токен  | Одна колода                                 |
| `PUT`    | `/decks/:id`     | токен  | Заменить название и карточки целиком        |
| `DELETE` | `/decks/:id`     | токен  | Удалить колоду вместе с карточками          |
| `GET`    | `/catalog`       | всем   | Готовые колоды: фильтры `language`, `topic`, `q`, `limit` (≤100), `offset` |
| `GET`    | `/catalog/:slug` | всем   | Одна каталожная колода вместе с карточками  |
| `POST`   | `/decks/from/:slug` | токен | Скопировать каталожную колоду себе       |
| `POST`   | `/cards/:id/review` | токен | Записать ответ по карточке: `{ "correct": true }` |
| `GET`    | `/decks/:id/due` | токен  | Карточки колоды, которые пора показать       |
| `GET`    | `/review/due`    | токен  | Просроченные карточки по всем колодам, `limit` (≤200) |

Тело для создания и обновления колоды:

```json
{
  "title": "Немецкий",
  "cards": [
    { "original": "der Hund", "translation": "собака" },
    { "original": "ねこ", "translation": "cat", "transcription": "neko" }
  ]
}
```

`transcription` необязательна. Пустая строка хранится как `NULL`, и в ответе
такого ключа просто нет — фронтенду не приходится отличать пустое от отсутствующего.

Колода в ответе повторяет тип `Deck` из фронтенда —
`{ id, title, cards, createdAt, dueCount }`, где `createdAt` в миллисекундах.
Порядок карточек сохраняется. `dueCount` — сколько карточек колоды пора
повторить прямо сейчас; для списка колод он считается одним запросом на все
колоды сразу, а не по запросу на колоду.

Чужие колоды недоступны: запрос к колоде другого пользователя отдаёт 404,
а не 403 — так по ответам нельзя узнать, какие id вообще существуют.

## Каталог готовых колод

Каталожная колода — обычная строка в `decks` с `is_public = true` и `slug`,
принадлежащая системному аккаунту `catalog@comfy-cards.local`. У него
`password_hash = '-'`: bcrypt на таком хеше всегда даёт `false`, войти под ним
нельзя. Отдельных таблиц под каталог нет намеренно — следующая крупная фича,
публичные колоды пользователей, ложится на тот же механизм.

`GET /catalog` отдаёт только счётчик карточек, без самих карточек: сотня наборов
по 75 слов утяжелила бы ответ на десятки килобайт, а списку они не нужны.
Карточки приходят в `GET /catalog/:slug`.

`POST /decks/from/:slug` копирует колоду на стороне сервера одним
`INSERT … SELECT`, не гоняя карточки через клиент. Это копия, а не подписка:
дальше колода личная, правки каталога в неё не приходят.

## Наполнение каталога

```bash
npm run seed
```

Скрипт читает `seed/*.json` и делает upsert по `slug` — идемпотентно, можно
гонять после каждой правки контента. Формат файла:

```json
{
  "slug": "hiragana",
  "title": "Hiragana",
  "description": "…",
  "language": "ja",
  "topic": "writing",
  "cards": [{ "original": "あ", "translation": "a" }]
}
```

Наполнить прод проще всего изнутри Railway — во вкладке **Console** сервиса
API, где `DATABASE_URL` уже подставлен, и пароль базы никуда не уезжает:

```bash
npm run seed:dist
```

Тот же скрипт, но из собранного кода: `tsx` для него не нужен. Снаружи можно
и так, подставив публичный `DATABASE_URL` сервиса Postgres:

```bash
DATABASE_URL="<public url>" npm run seed
```

## Тесты

```bash
DATABASE_URL="postgres://postgres@127.0.0.1:5433/comfy_test" \
JWT_SECRET="local-test-secret-at-least-32-characters" npm test
```

Тесты поднимают приложение через `fastify.inject`, гоняют миграции и seed, и
**стирают данные** в указанной базе — поэтому они откажутся работать, если
`DATABASE_URL` не смотрит на localhost или на базу со словом `test` в имени.

## Интервальные повторения

Коробки Лейтнера. У пары «пользователь + карточка» есть номер коробки, интервал
и время следующего показа — таблица `card_reviews`. Правильный ответ двигает
карточку на коробку вперёд, неправильный возвращает в нулевую:

| Коробка | 0 | 1 | 2 | 3 | 4 | 5 |
| --- | --- | --- | --- | --- | --- | --- |
| Через сколько дней | сразу | 1 | 3 | 7 | 14 | 30 |

Выбраны коробки, а не SM-2: с фронта приходит бинарный ответ «угадал / не
угадал», а SM-2 нужны оценки от нуля до пяти, которых в интерфейсе нет. Сам
расчёт лежит в чистой функции `nextReview` в `src/lib/scheduler.ts` — заменить
алгоритм можно, не трогая ни маршруты, ни запросы.

`GET /decks/:id/due` отдаёт карточки, у которых срок подошёл, и те, которые
никогда не показывались: у новой карточки записи в `card_reviews` просто нет,
и она считается просроченной. Сначала идут самые просроченные, новые карточки
в конце.

`GET /review/due` — то же самое, но по всем колодам сразу, для общего экрана
«что повторить сегодня». Каждая карточка приходит с `deckId` и `deckTitle`,
рядом лежит `total` — сколько всего просрочено, независимо от `limit`.

Сохранение колоды больше не пересоздаёт карточки: `PUT /decks/:id` сверяет
присланный список с тем, что лежит в базе, и оставляет прежние `id` тем
карточкам, у которых не изменились слово, перевод и транскрипция. Иначе любая
правка колоды обнуляла бы всю историю повторений. Отредактированная карточка
считается новой — прогресс по ней начинается заново.

## Структура

- `src/routes` — HTTP-слой: разбор входа и коды ответов
- `src/db` — работа с базой, по файлу на сущность; `pool.ts` даёт `withTransaction`
- `src/lib` — переменные окружения, пароли, ошибки, валидация
- `src/plugins/auth.ts` — JWT и хук `app.authenticate`
- `src/lib/scheduler.ts` — расчёт следующего показа, без обращений к базе
- `migrations` — SQL по возрастанию номера, применяются один раз под
  advisory-локой, поэтому две одновременно стартующие реплики не столкнутся
- `seed` — содержимое каталога, по файлу на колоду
- `tests` — интеграционные тесты через `fastify.inject`

## Деплой на Railway

1. Создать сервис из этого репозитория
2. Добавить в проект PostgreSQL — Railway сам подставит `DATABASE_URL`
3. Задать `JWT_SECRET` (`openssl rand -base64 32`) и `WEB_ORIGIN` — адрес фронтенда
4. Сгенерировать домен в Settings → Networking

Конфиг в `railway.json`: сборка `npm run build`, запуск `npm start`,
healthcheck на `/health`. Node берётся из `.nvmrc`.

В `nixpacks.toml` фаза установки переопределена на `npm install`: штатный
`npm ci` падает, если lock-файл собран другой версией npm, чем стоит в
образе сборки.
